# 02 — Data sources

## The headline: there is no dataset to acquire

Training and evaluation data is **simulated**. This is not a compromise — it is the
methodologically correct choice for this project, for three reasons:

1. **Ground truth is known.** Under Black–Scholes with zero costs, the optimal hedge *is*
   the BS delta. That gives a hard correctness gate (rung 4 of the ladder) that no
   real-data project can have. You can tell whether your implementation is right, rather
   than guessing.
2. **The research question is about controlled comparison.** Fixing the data-generating
   process is the entire point of a benchmark protocol. Real data would introduce exactly
   the uncontrolled variation the paper is criticising.
3. **Zero cost, zero licensing, zero access risk.** No vendor, no NDA, no waiting on an
   institutional subscription to start work.

Real market data enters at **Stage 5+ only**, for a bounded "does this survive contact
with reality" section.

---

## Primary: simulated

Generated by `dhbench/worlds/`. All use `tf.random.Generator` with an explicit seed passed
in — never global random state, because bit-reproducibility is a headline claim.

| World | Module | Parameters to fix in `configs/` |
|:--|:--|:--|
| Geometric Brownian motion | `worlds/gbm.py` | $S_0, \mu, \sigma, T, n_{\text{steps}}$ |
| Heston stochastic volatility | `worlds/heston.py` | $v_0, \kappa, \theta, \xi, \rho$ |
| Regime-switching | `worlds/regime_switching.py` | per-regime $(\mu, \sigma)$, transition matrix |
| Jump-diffusion (Merton) | `worlds/jumps.py` | $\lambda_{\text{jump}}, \mu_J, \sigma_J$ |

**Calibration.** GBM and Heston parameters should be *plausible*, not arbitrary — calibrate
Heston once against a real SPX implied-vol surface and freeze those values in the config.
That single calibration is the only place real data is needed before Stage 5, and a
published parameter set from the literature is an acceptable substitute.

## Secondary: real market data (Stage 5+)

Used to answer one question — *does a policy trained on simulated paths hold up on realised
ones?* — and nothing more.

| Source | What you get | Cost | Notes |
|:--|:--|:--|:--|
| **Deribit API** | BTC/ETH options, full order history | **free, no API key** | Best free options data anywhere. Crypto, so the microstructure differs from equities — state that as a limitation |
| **OptionsDX** | End-of-day SPX option chains | free tier | What the 2026 regime-fragility paper used. Good precedent to cite |
| **CBOE DataShop** | SPX options, index data | free samples, paid full | Sample files are enough for a validation section |
| **WRDS / OptionMetrics (IvyDB)** | The academic standard for options research | **institutional** | ⭐ **Check Stevens' subscription.** If available, this materially strengthens §7 and is what reviewers expect |
| **yfinance** | Underlying spot histories | free | Calibration and realised-vol series only. Not for option prices — the chains are unreliable |
| **FRED** | Risk-free rate curve | free | For $r$; don't just assume zero |

### Data hygiene, if real data is used

- Nothing downloaded goes into git. `.gitignore` already excludes `*.npz`, `*.pkl`,
  `experiments/runs/`.
- Every real dataset gets its retrieval script committed and its retrieval date recorded
  here. "I downloaded some SPX data" is not reproducible.
- Check the license before redistributing anything. Deribit is permissive; OptionMetrics
  is emphatically not.

## Compute

Not data, but the other resource constraint, and it shapes what's feasible.

| Stage | Needs | Where |
|:--|:--|:--|
| 0–2 | CPU only | local venv |
| 3+ | GPU | **Google Colab** (free T4) |
| 5 (full grid) | many GPU-hours | Colab Pro, or ask Stevens about HPC allocation |

**The local machine cannot do GPU TensorFlow.** It has an AMD Radeon 860M (Ryzen AI 7 350,
Krackan Point, gfx1152):

- AMD's official [ROCm WSL compatibility matrix](https://rocm.docs.amd.com/projects/radeon-ryzen/en/latest/docs/compatibility/compatibilityrad/wsl/wsl_compatibility.html)
  lists **discrete cards only** — no integrated GPU appears on it.
- `librocdxg` 1.2 (May 2026) *did* add the GFX11.5.2 target, which is this architecture —
  so it may work unofficially. Not something to bet a thesis on.
- `tensorflow-directml-plugin`, the other AMD-on-Windows route, has had
  [development paused](https://github.com/microsoft/tensorflow-directml-plugin).

Plan for Colab from Stage 3. Budget the Stage 5 grid explicitly — it is hundreds of
training runs, and the paper must state the compute budget as a stated limitation (§9).
